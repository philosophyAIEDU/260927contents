# /ingest — 새 콘텐츠 정제·태깅·업로드

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). 반드시 `CLAUDE.md`의 필수 태그·규칙 1~3을 따른다.

## 실행 모드
- `/ingest` (기본 모드): 아래 0~5단계를 따르며, 애매한 것은 묻고 태깅 표를 확인받은 뒤 진행한다.
- `/ingest auto` (자동 모드): 인자에 `auto`가 있으면 **아래 "자동 모드" 섹션이 기본 모드의 확인·질문 단계를 대체**한다. 사용자에게 질문하지 않고 끝까지 진행한다. `auto` 뒤에 유튜브 링크가 있으면 그 링크의 대본을 먼저 받는다 (0단계).

## 0. 시작 전
- `raw/`에서 `processed/`에 아직 없는 파일을 찾는다 (`processed/*.json`의 `source_file`과 비교). 댓글은 `raw/comments/`이므로 여기서 다루지 않는다.
- 사용자가 유튜브 링크만 준 경우: `python -m yt_dlp --skip-download --write-auto-subs --sub-langs ko-orig --sub-format json3 -o <임시경로> <링크>`로 한국어 자동 자막을 받아 `raw/대본 N.txt`(UTF-8, 한 줄에 한 구간, 연속 중복 제거)로 저장한다. `[음악]` 같은 비음성 표시는 뺀다. 영상 채널이 내 채널(`.env`의 `MY_YOUTUBE_CHANNEL_ID`)이 아니면 **멈추고 확인**한다(규칙 3).

## 1. 종류 판별
읽어 보고 다음 중 하나로 정한다. 애매하면 추측하지 말고 묻는다.
- **대본**: 말하는 문체, "안녕하세요 ... 오늘은", "좋아요와 구독" 같은 영상 마무리 → `format: 유튜브 대본`
- **뉴스레터**: 인사말/메인/나의 생각/다음 예고 같은 구성 → `format: 뉴스레터`
- **스레드**: 짧은 글 여러 개가 이어진 SNS 글 → `format: 스레드`
- 타인이 쓴 글이나 유료 콘텐츠로 보이면 처리를 멈추고 확인한다 (규칙 3).

## 2. 정제
- `raw/`는 절대 수정하지 않는다. 정제본은 `processed/<id>.json`에만 만든다.
- id 규칙: `script-NN`, `newsletter-NN`, `thread-NN` (기존 최대 번호 + 1).
- 공통: 빈 줄 제거, 자리표시 문구(예: "클릭해서 이미지를 올려주세요") 제거.
- 자동 자막 대본: 문맥상 **확실한** 용어 오인식(제품명·고유명사)만 고친다. 확정할 수 없는 곳은 그대로 두고 목록으로 보고한다. 원문(raw)에는 손대지 않는다.

## 3. 태깅 (표로 먼저 보여주고 확인받기)
필수 태그 6개: `category`, `format`, `target_audience`, `performance_grade`, `published_at`, `key_message`.
- 판단이 애매한 태그(카테고리, 타깃 등)는 **추측하지 말고 물어본다**. 제안값은 "제안"이라고 표시한다.
- 카테고리는 기존 `processed/*.json`의 값을 먼저 재사용한다. 새 카테고리가 필요하면 그렇다고 알린다.
- 유튜브 대본은 `youtube_url`이 있으면 발행일·조회수·성과등급을 API로 채운다:
  `node --env-file=.env scripts/enrich.mjs --id <id> --url <링크>` (등급 기준은 `/grade` 참고)
- 뉴스레터·스레드처럼 자동으로 못 채우는 값(발행일, 등급)은 사용자에게 묻는다. 모르면 `null`로 두고, 그 상태로는 업로드하지 않는다 (사용자가 명시적으로 허용할 때만 `--allow-missing <태그>`).
- **표를 보여주고 사용자가 확인하기 전에는 `processed/`에 저장하지 않는다.** 여러 편이면 표 하나에 모아서 한 번에 확인받는다.

## 4. 저장과 업로드
1. 확인이 나면 `processed/<id>.json`을 저장한다. 구조: `id`, `source_file`, `youtube_url`(있으면), `tags{6개}`, `views`, `upload_ready`, `missing_tags`, `body`.
2. dry-run: `node scripts/upload.mjs --id <id>` (검증과 중복·개인정보 패턴 검사만). 실패하면 이유를 알리고 멈춘다.
3. **검수 에이전트 호출 (필수)**: `--commit` 전에 반드시 `data-checker` 에이전트(Agent 도구, `subagent_type: "data-checker"`)를 호출한다. 프롬프트에 검사할 id 목록과, 사용자가 허용한 누락 태그가 있으면 그 이름을 적는다.
   - 보고서의 `판정: 업로드 중단`이면 **업로드하지 않는다.** 문제를 한글로 그대로 전하고, 고칠 방법(예: 개인정보 삭제, 중복 문서 확인, `/takedown`)을 제안한다. 고친 뒤 검수를 다시 돌린다. 중복·개인정보 문제는 사용자가 "그냥 올려"라고 해도 올리지 않고, 고치거나 해당 부분을 뺀 뒤 다시 검수한다.
   - `판정: 통과`이지만 "확인 필요" 항목이 있으면 사용자에게 보여주고 답을 받은 뒤 진행한다.
   - "덮어쓰기 예정인 문서"가 있으면 사용자에게 알린다.
4. 검수를 통과하고 사용자가 확인하면 업로드한다. 설정(Firebase 프로젝트 ID, 서비스 계정 키 경로)은 `.env`에 있고 내용은 읽지 않는다.
   `node --env-file=.env scripts/upload.mjs --id <id> --commit`
   (`--commit`은 Firestore의 기존 문서와도 다시 비교하고, 문제가 있으면 아무것도 쓰지 않고 멈춘다.)
5. 대상은 Firestore(`.env`의 `FIREBASE_PROJECT_ID`)의 `contents_input` (관리자 전용).

## 5. 기록
`reports/ingest-log.md` 맨 아래에 한 항목을 추가한다: 날짜, id, 원본 파일, 종류, 태그 요약, 수정한 용어 수/미수정 목록, 검수 결과(통과/중단과 사유), 업로드 결과, 비어 있는 태그.

## 자동 모드 (`/ingest auto`)

**원칙: 물어보지 않는다. 확신할 수 없으면 올리지 않고 보류한다.** 잘못 올리는 것보다 보류가 항상 낫다. 기본 모드와 같은 검사·규칙을 쓰되, 사람이 답해야 하는 지점은 전부 "보류"로 바뀐다.

### A. 대상 찾기
- `raw/` 최상위의 `.txt`/`.md` 파일 중 `processed/*.json`의 `source_file`에 없는 것이 대상이다. **제외**: `raw/hold/`, `raw/comments/`(댓글은 `/ingest-comments`), `*.meta.json`, `.gitkeep`.
- 인자에 유튜브 링크가 있으면 0단계로 자막을 받아 `raw/대본 N.txt`를 먼저 만든다 (`hold/`의 파일 번호도 포함해 N을 정해 이름이 겹치지 않게 한다). 채널이 내 채널(`MY_YOUTUBE_CHANNEL_ID`)이 아니거나 자막이 없으면 그 링크는 **보류/실패**로 기록한다 (받은 파일이 없으면 옮길 것도 없이 로그만 남긴다).
- 대상이 하나도 없으면 "처리할 새 파일 없음"을 로그에 남기고 끝낸다.
- 선택 입력: 파일 옆의 `raw/<파일명>.meta.json` (예: `{"youtube_url": "...", "published_at": "2026-09-01", "views": 1200, "performance_grade": "상"}`). 있으면 발행일·조회수·등급에 쓴다. 등급이 없고 조회수만 있으면 100 미만 하 / 100~999 중 / 1000 이상 상으로 계산한다.

### B. 파일마다 독립 처리 (하나가 실패해도 다음 파일로 계속)
1. 종류 판별 → 정제 → 태깅을 기본 모드와 같은 기준으로 하되, **표를 보여주지 않고 확인도 받지 않는다.** id는 processed의 최대 번호 + 1 (같은 실행 안에서 순서대로 증가).
2. 유튜브 링크(인자 또는 `.meta.json`)가 있으면 `enrich.mjs`로 발행일·조회수·등급을 채운다.
3. **"애매함" = 보류.** 다음 중 하나라도 해당하면 추측하지 말고 보류한다.
   - 종류(대본/뉴스레터/스레드)가 명확하지 않거나 둘 이상으로 읽힌다.
   - `category`가 확정된 목록(`.claude/skills/taxonomy/taxonomy.md`)이나 기존 `processed/`의 값 중 **명확히 맞는 것이 없다.** 자동 모드는 **새 카테고리를 만들지 않는다.**
   - `target_audience`도 기존 값 중 명확히 맞는 것이 없다 (새 값 만들지 않음).
   - `published_at`이나 `performance_grade`를 채울 방법이 없다 (유튜브 링크·`.meta.json` 없음). 뉴스레터·스레드가 대개 여기에 해당한다.
   - `key_message`를 본문에서 한 문장으로 확정하기 어렵다 (내용이 너무 짧거나 여러 주제).
   - 타인의 글·유료 콘텐츠로 의심되거나 유튜브 채널이 내 채널(`MY_YOUTUBE_CHANNEL_ID`)이 아니다 (규칙 3).
   - `--allow-missing`은 **자동 모드에서 쓰지 않는다.** 필수 태그가 하나라도 비면 보류다.
4. 애매하지 않으면 `processed/<id>.json`을 저장하고 `node scripts/upload.mjs --id <id>`로 dry-run 한다. 실패하면 보류(사유: 검증 실패 내용).
5. **`data-checker` 에이전트를 호출**한다 (`subagent_type: "data-checker"`, 허용 누락 태그 없음). 다음이면 **보류**한다.
   - `판정: 업로드 중단`
   - `판정: 통과`여도 "확인 필요" 항목이 있다 (자동 모드는 답을 받을 수 없다)
   - "덮어쓰기 예정" 문서가 있다 (자동 모드는 기존 문서를 덮어쓰지 않는다)
6. 통과하면 `node --env-file=.env scripts/upload.mjs --id <id> --commit`로 올린다 (키 파일(`keys/`) 내용은 읽지 않는다). 성공 → **업로드 성공**.
7. 명령이 오류로 끝나면(네트워크·API·권한 등) **실패**로 기록한다. 이번 실행에서 새로 만든 `processed/<id>.json`은 지워서(원본 raw는 그대로) 다음 실행에서 다시 시도되게 한다. 이미 Firestore에 올라갔는지 불확실하면 지우지 말고 로그에 "업로드 여부 불확실"이라고 적는다.

### C. 보류 처리 (`raw/hold/`)
- 보류한 파일의 원본과 있다면 `.meta.json`을 `raw/hold/`로 **옮긴다** (없으면 `mkdir -p raw/hold`). 내용은 수정하지 않는다. 같은 이름이 이미 있으면 뒤에 `-2`를 붙인다.
- 옆에 `raw/hold/<파일명>.hold.txt`를 만들어 **보류 사유를 한글로** 적는다 (날짜, 어떤 기준에 걸렸는지, 사람이 결정해야 할 것).
- 이미 저장했던 `processed/<id>.json`이 있으면 `processed/_hold/`로 옮긴다 (Firestore에는 올리지 않은 상태여야 한다).
- 보류한 파일은 다음 `/ingest auto`에서 **다시 처리되지 않는다** (`raw/hold/`는 대상 제외). 사람이 사유를 해결하면 파일을 `raw/`로 되돌리거나 `/ingest`(기본 모드)로 처리한다.

### D. 기록 (`reports/ingest-log.md`, 날짜별)
- 파일 맨 아래에서 오늘 날짜의 `## YYYY-MM-DD /ingest auto` 제목을 찾는다. 없으면 만들고, 있으면 그 아래에 이어 쓴다. 날짜와 시각은 `date` 명령으로 얻는다.
- 그 아래에 이번 실행을 `### 실행 HH:MM` 소제목으로 추가하고, 표로 적는다.

```
| 파일 | 결과 | id | 사유·요약 |
|---|---|---|---|
| 대본 6.txt | 업로드 성공 | script-06 | AI 활용 / 상(3,210회) / 발행 2026-09-20, 교정 12줄 |
| 뉴스레터 2.txt | 보류 | - | 발행일·성과등급을 채울 수 없음 → raw/hold/ |
| 대본 7.txt | 보류 | - | data-checker: 본문에 전화번호 형태 → raw/hold/ |
| 대본 8.txt | 실패 | - | 유튜브 API 오류 (raw 그대로, 다음 실행에서 재시도) |
```
- 결과는 **업로드 성공 / 보류 / 실패** 셋 중 하나만 쓴다. 개인정보는 값이 아니라 종류와 위치만 적는다.
- 표 아래에 한 줄 합계를 적는다: `합계: 성공 N · 보류 N · 실패 N`.

### E. 마무리 보고 (채팅)
성공/보류/실패 건수와 파일별 한 줄 요약, **보류 사유**, 사람이 해야 할 일을 짧게 알린다. 질문으로 끝내지 않는다.

## 금지
- 자동 모드에서 사용자 확인 없이 진행하는 것은 위 절차 범위 안에서만 허용된다. 그 밖의 동작(삭제, 덮어쓰기, `--allow-missing`, 새 카테고리 생성, 검수 건너뛰기)은 하지 않는다.
- `.env`, `keys/`의 내용을 읽거나 출력하지 않는다. 채팅에 키를 붙이지 않는다.
- 필수 태그가 비어 있는 채로 조용히 올리지 않는다.
- 사용자 확인 없이 `--commit` 하지 않는다.
