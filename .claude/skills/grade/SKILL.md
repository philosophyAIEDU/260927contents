# /grade — 성과등급 갱신

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더).

## 등급 기준 (사용자가 정한 값)
조회수 기준:
- 100 미만 → **하**
- 100 이상 1000 미만 → **중**
- 1000 이상 → **상**

**시청 지속률 등 다른 지표는 등급 기준이 정해져 있지 않다.** 사용자가 지표를 주더라도 임의의 기준을 만들지 않는다.
- 지속률을 등급에 반영하려면 먼저 기준을 묻는다 (예: "지속률 몇 % 이상이 상인가요?"). 답을 받으면 `CLAUDE.md`의 등급 기준 항목에 적어 둔다.
- 기준이 없으면 지속률은 `retention_percent` 필드에 **기록만** 하고 등급은 조회수로만 정한다.

## 절차
1. **대상 찾기**: 사용자가 준 영상 제목(또는 id)을 `processed/*.json`에서 찾는다. `youtube_url`에서 확인되는 영상 제목이나 `source_file`, `key_message`로 대조한다. 후보가 여러 개면 목록을 보여주고 고르게 한다. 없으면 `/ingest`가 필요하다고 알린다.
2. **수치 얻기**
   - 조회수: 사용자가 준 값을 우선 쓴다. 안 줬고 `youtube_url`이 있으면 `node --env-file=.env scripts/enrich.mjs --id <id>`로 API에서 최신 조회수를 가져온다 (발행일도 함께 확인됨).
   - 시청 지속률 등: 사용자가 준 값만 쓴다 (API로는 가져오지 못한다).
3. **변경 표 보여주기**: id, 제목, 이전 조회수/등급, 새 조회수/등급을 표로 보여주고 확인받는다. 등급이 바뀌지 않으면 그렇게 알린다. 확인 전에는 저장하지 않는다.
4. **저장**: `processed/<id>.json`의 `views`, `views_fetched_at`, `tags.performance_grade`(필요하면 `retention_percent`)를 갱신한다. 다른 필드는 건드리지 않는다.
5. **업로드**: `node scripts/upload.mjs --id <id>`로 dry-run 검증 후, 확인이 나면 `node --env-file=.env scripts/upload.mjs --id <id> --commit`. 키 파일(`keys/`)의 내용은 읽지 않는다. 경로는 `.env`에 있다.
6. **여러 편 갱신**: "전체 갱신"이면 `node --env-file=.env scripts/enrich.mjs --all` 후 바뀐 문서만 표로 보여주고, 확인받아 바뀐 문서만 올린다.
7. **댓글 문서**: `format: 댓글`의 등급은 부모 콘텐츠를 따른다. 부모 등급이 바뀌면 그 댓글 문서(`parent_id`가 같은 문서)도 같이 갱신할지 물어본다.

## 기록
`reports/ingest-log.md` 맨 아래에 추가한다: 날짜, id, 이전→이후 조회수·등급, 사용한 수치의 출처(사용자 입력/API), 업로드 결과.

## 금지
- 기준이 없는 지표로 등급을 임의 판단하지 않는다.
- 사용자 확인 없이 `--commit` 하지 않는다.
- `.env`, `keys/`의 내용을 읽거나 출력하지 않는다.
