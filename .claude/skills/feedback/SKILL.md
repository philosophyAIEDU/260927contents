# /feedback — 발행 후 성과 기록 (발행 7~14일 뒤)

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). 이 스킬은 **대화형**이다. 필요한 것만 짧게 묻는다.

## 왜 하는가
초고를 만들고 끝나면 엔진이 자라지 않는다. 발행 후 성과와 "실제로 얼마나 고쳤는지"를 다시 넣어야 `structure.md`·`voice.md`를 고칠 근거가 생긴다. 모든 지표를 보지 않고 **채널별 핵심 지표 하나**만 본다.

## 절차
1. **어떤 초고인가**: `drafts/` 아래 최근 초고 파일을 보여 주고 고르게 한다 (직접 쓴 글이라 초고가 없으면 "초고 없음"으로 진행). 채널은 파일 위치(`thread`/`newsletter`/`script`)로 안다.
2. **발행 정보**: 발행일, 유튜브라면 영상 링크. 발행한 지 7일 미만이면 "너무 이르다"고 알리고 계속할지 묻는다 (데이터가 덜 쌓이므로).
3. **얼마나 고쳤는가**: 다음 중 하나를 고르게 한다.
   - 거의 그대로 (약 20% 이하 수정) / 일부 수정 (20~50%) / 대폭 수정 (50% 초과) / 새로 씀
   - 실제 발행본 텍스트나 파일 경로를 주면 초고와 비교해 대략의 수정 비율을 계산한다 (`python`의 `difflib.SequenceMatcher`, 대략치라고 밝힌다). 수정 비율이 크면 어디를 고쳤는지 1~3가지를 묻는다.
4. **성과 수치**: `CLAUDE.md`의 "성과 지표"를 읽는다.
   - 핵심 지표가 합의돼 있으면 그 수치를 받는다.
   - 합의 전이면 **제안값**(스레드 저장 수 / 뉴스레터 클릭률 / 유튜브 시청 지속률)을 보여 주고 어떤 지표를 쓸지 묻는다. 합의된 지표는 사용자가 확정하면 `CLAUDE.md` "성과 지표"에 적는다.
   - 유튜브는 링크가 있으면 `enrich.mjs`로 조회수·발행일을 가져올 수 있다 (`node --env-file=.env scripts/enrich.mjs --id <id> --url <링크>`는 processed 문서가 있을 때).
5. **저장**: 아래 내용을 `reports/feedback/<날짜>_<슬러그>.json`으로 저장하고, `node scripts/save-output.mjs --file <경로>`로 dry-run 한 뒤 통과하면 `node --env-file=.env scripts/save-output.mjs --file <경로> --commit`으로 Firestore `contents_output`에 올린다. 관리자 페이지(`admin/index.html`)의 Contents Output 탭에 "성과 피드백"으로 보인다.

```
{ "title": "[성과] 스레드 · <주제>", "type": "성과 피드백",
  "sourceIds": ["<관련 processed id가 있으면>"],
  "body": "발행일, 수정 정도, 지표와 수치, 메모를 읽기 쉽게 요약",
  "meta": { "channel": "thread", "draft_file": "drafts/thread/...", "published_at": "YYYY-MM-DD",
            "edit_level": "일부 수정", "edit_ratio_estimate": 0.3,
            "metric": "저장 수", "value": 42, "grade": "상|중|하|null", "days_after_publish": 10 } }
```
6. **성과등급 갱신**
   - 유튜브(조회수 기준이 있음): 발행본이 `processed/`에 있으면 `/grade`와 같은 절차로 등급을 다시 계산해 반영한다. 없으면 "`/ingest <링크>`로 올리면 등급이 자동으로 채워진다"고 안내한다.
   - 스레드·뉴스레터·시청 지속률: **등급 기준이 `CLAUDE.md`에 있을 때만** 상/중/하를 매긴다. 없으면 `grade: null`로 기록하고, "이 지표의 상/중/하 기준을 정해 주시면 다음부터 자동으로 매긴다"고 알린다. 기준을 임의로 만들지 않는다.
7. **규칙으로 남길 피드백**: 3번에서 나온 수정 이유(예: "첫 줄이 너무 친절해서 고쳤다") 중 앞으로도 적용할 만한 것은 `reports/monthly/inbox.md`에 날짜와 함께 한 줄씩 추가한다 (파일이 없으면 만든다). `voice.md`·`structure.md`는 **여기서 직접 고치지 않는다.** 월간 리뷰가 이 목록을 함께 보고, 승인은 사용자가 한다.
8. **마무리 보고**: 저장한 곳, 등급 갱신 여부, `inbox.md`에 남긴 항목을 짧게 알린다.

## 금지
- 성과 수치를 지어내거나 추정해서 채우지 않는다. 모르면 비운다.
- 기준 없는 지표로 등급을 매기지 않는다.
- `voice.md`, `structure.md`를 수정하지 않는다.
