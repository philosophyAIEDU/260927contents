# /menu — 스킬·에이전트 메뉴

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). **읽기 전용**이다.

## 절차
1. `.claude/skills/*/SKILL.md`와 `.claude/agents/*.md`의 머리말(`name`, `description`)을 읽어 **현재 존재하는 목록**을 확인한다. (`_common/`처럼 `SKILL.md`가 없는 폴더는 스킬이 아니다.)
2. 아래 "처음 시작하는 순서"부터 보여주고, 이어서 나머지 표를 보여준다.
3. 표와 실제 목록을 비교한다.
   - 실제로는 있는데 표에 없는 항목은 표 맨 아래에 같은 형식으로 덧붙여 보여주고 "표에 없는 항목이라 임시로 추가했다"고 알린다.
   - 표에는 있는데 실제로는 없는 항목은 그 행에 "(현재 없음)"이라고 표시한다.
   - 어긋난 것이 있으면 이 파일의 표를 고칠지 물어본다. **묻기 전에는 파일을 수정하지 않는다.**
4. 사용자가 특정 명령의 자세한 사용법을 물으면 그 스킬의 `SKILL.md`를 읽어 요약해 설명한다.

## 처음 시작하는 순서 (이 5개면 충분하다)

전체 흐름은 **모으기(Input) → 분석 → 아이디어 → 초고(Output)** 입니다.

| 순서 | 명령어 | 하는 일 | 예시 |
|---|---|---|---|
| 1 | `/ingest` | 내 대본·뉴스레터·스레드를 정리하고 태그를 붙여 Firebase의 **Contents Input**에 올린다 | `raw/`에 파일을 넣고 `/ingest` |
| 2 | `/analyze-style` | 올린 콘텐츠를 분석해 내 말투(`voice.md`)와 성공 패턴(`structure.md`)을 채운다 | `/analyze-style` |
| 3 | `/topic-ideas` | Input을 근거로 다음 콘텐츠 주제 후보 5개를 제안한다 | `/topic-ideas` |
| 4 | `/thread-draft` `/newsletter-draft` `/script-draft` | 주제 한 줄로 초고를 쓴다. 검수 후 **Contents Output에 자동 저장**된다 | `/thread-draft 초보자가 AI로 첫 앱을 만드는 순서` |
| 5 | (관리자 페이지) | Input과 Output을 웹에서 확인하고, 초고를 20% 손질해 발행한다 | `admin/index.html` |

## 그 밖의 명령

| 명령어 | 한 줄 설명 | 사용 예시 | 언제 쓰는지 |
|---|---|---|---|
| `/menu` | 이 목록을 보여준다 | `/menu` | 뭐부터 해야 할지 헷갈릴 때 |
| `/status` | 올라간 편수, 빠진 태그, 아직 처리하지 않은 raw 파일을 보여준다 (읽기 전용) | `/status` | 지금 어디까지 했는지 확인할 때 |
| `/audit` | 키 유출, 댓글 작성자 정보, 타인·유료 콘텐츠 위반을 점검한다 (읽기 전용) | `/audit` | GitHub에 올리기 전이나 정기 점검 때 |
| `/takedown` | 잘못 올린 콘텐츠를 Firestore에서 삭제하고 `processed/_removed/`로 치운다 | `/takedown script-06` | 타인 글·개인정보를 실수로 올렸거나 중복 문서를 지울 때 (삭제 전 반드시 확인) |
| `/make-output` | 초고나 새 결과물을 Contents Output에 저장한다 | `/make-output drafts/thread/2026-10-05_주제.md` | 초고를 손질한 뒤 다시 올리거나, 자동 저장이 실패했을 때 |
| `/ingest auto` | 질문 없이 자동으로 처리한다. 애매한 파일은 `raw/hold/`로 옮긴다 | `/ingest auto` | 파일이 여러 개라 한꺼번에 처리하고 싶을 때 |

## 에이전트 (스킬이 알아서 부른다)

| 에이전트 | 하는 일 | 언제 |
|---|---|---|
| `data-checker` | 업로드 직전에 필수 태그, 중복, 개인정보를 검수하고 문제가 있으면 멈추라고 알린다 | `/ingest`, `/ingest-comments`가 자동 호출 |
| `voice-checker` | 초고가 내 말투인지, 금칙어·"누구나 쓸 법한 글"이 없는지 검수한다 | 초고 저장 직후 자동 호출 |
| `risk-checker` | 성과 보장·과장, 댓글 작성자·시청자 노출, 근거 없는 수치를 검수한다 | 초고 저장 직후 자동 호출 |

직접 부르려면 "이 초고 voice-checker로 검수해줘"처럼 말하면 된다.

## 주간 루틴 (예시)

| 시점 | 할 일 | 방식 |
|---|---|---|
| 새 콘텐츠를 발행했을 때 | 원본을 `raw/`에 넣고 Input에 올린다 | `/ingest` |
| 주 1회 | 주제 후보를 보고 초고를 만든다 | `/topic-ideas` → `/thread-draft` 등 |
| 발행 후 7~14일 | 성과 입력 | `/feedback` |
| 월 1회 | 규칙 파일 수정안 확인 | `/monthly-review` |
| 기억 안 날 때 | 명령어 안내 | `/menu` |

## 자동화(예약 실행)는 선택 사항
`/weekly-drafts`, `/ingest auto`, `/monthly-review prep`은 질문 없이 끝까지 실행되므로 Claude Code의 예약 작업(Routines)에 등록해 정해진 요일에 돌릴 수 있다. 작업 폴더는 이 프로젝트 폴더로 지정하고, 앱이 열려 있고 컴퓨터가 깨어 있을 때만 실행된다. 처음에는 등록하지 말고 직접 몇 번 써 본 뒤에 정하는 것을 권한다. **자동 실행은 `voice.md`·`structure.md`를 절대 바꾸지 않는다** (수정안은 `reports/monthly/`에 저장되고 승인은 사람이 한다).

## 참고
- 스킬은 `/이름`으로 부르고, 에이전트는 스킬이 자동으로 호출하거나 "voice-checker로 검수해줘"처럼 말해서 부른다.
- 스킬 파일을 새로 만들거나 고친 뒤 목록에 나타나지 않으면 Claude Code를 다시 시작한다.
- 보조 스크립트(`scripts/`)는 스킬이 알아서 쓰므로 보통 직접 실행하지 않는다.
- 초고 스킬이 공통으로 따르는 절차는 `.claude/skills/_common/draft-review.md`에 있다 (스킬이 아니라 참고 문서).
