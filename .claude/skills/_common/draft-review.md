# 초고 스킬 공통 절차

`/thread-draft`, `/newsletter-draft`, `/script-draft`, `/repurpose`, `/weekly-drafts`가 함께 따른다. (이 폴더에는 `SKILL.md`가 없어서 스킬이 아니라 참고 문서다.)

## 1. 준비 (초고를 쓰기 전에 반드시)
1. `CLAUDE.md`의 "초고 작성 (Output)" 섹션(규칙 4~6)을 읽는다.
2. `voice.md`(말투, 특히 금칙어 7절)와 `structure.md`(전개 패턴)를 끝까지 읽는다. **둘 중 하나라도 없거나 비어 있으면 멈추고** "voice.md/structure.md가 먼저 필요하다"고 알린다. 지어내서 쓰지 않는다.
3. 오늘 날짜는 `date +%Y-%m-%d`로 얻는다.

## 2. 근거 자료 (지어내지 않기)
- 사실·예시·수치는 `processed/*.json`의 본문과 태그(성과 등급 '상' 우선, 같은 카테고리·주제)에서만 가져온다. 사용자가 실제로 만든 앱·화면·경험을 우선한다.
- 자료에 없는 수치, 기능, 요금, 출시일은 쓰지 않는다. 꼭 필요하면 "[확인 필요: ...]"로 표시한다 (규칙 5).
- 댓글·문의 문서는 **어떤 질문이 많은지 패턴**으로만 참고한다. 원문 문장을 옮기거나 특정인이 떠오르는 사례를 쓰지 않는다 (규칙 4).
- 초고를 쓴 뒤 `voice.md` 금칙어와 이모지가 남아 있지 않은지 스스로 한 번 훑는다 (규칙 6).

## 3. 저장 형식
경로: `drafts/<채널>/<날짜>_<주제슬러그>.md` (`<채널>`은 `thread` / `newsletter` / `script`).
- 슬러그: 주제에서 `\ / : * ? " < > |`를 뺀 뒤 공백은 `-`로 바꾸고 40자 이내로 자른다.
- 같은 이름이 이미 있으면 덮어쓰지 말고 `-2`, `-3`을 붙인다.

```
# <주제> — <채널> 초고

- 작성일: YYYY-MM-DD
- 채널: 스레드 | 뉴스레터 | 유튜브 대본
- 상태: 초고 (사용자가 20% 손질한 뒤 발행)
- 근거 자료: script-04, script-05 (사용한 processed 문서 id)

## 초고
(본문)

## 적용한 규칙
- 말투: (적용한 voice.md 규칙 2~4개, 예: "여러분" 대신 "분들", 8~11어절 문장)
- 구조: (적용한 structure.md 패턴, 예: 훅 유형 B, 결과 먼저 → 의미)
- 참고한 콘텐츠: (id와 이유)

## 검수 메모
(4단계에서 채운다)
```

## 4. 검수 (저장 직후, 필수)
1. 초고를 저장한다. 검수 메모 자리는 `(검수 중)`으로 둔다.
2. **한 번의 응답에서 두 에이전트를 동시에** 호출한다 (Agent 도구).
   - `subagent_type: "voice-checker"` — 프롬프트: 초고 파일 경로와 채널
   - `subagent_type: "risk-checker"` — 프롬프트: 초고 파일 경로와 채널
   - 파일이 여러 개(예: `/repurpose`)면 파일마다 두 에이전트를 모두 호출한다.
3. 보고서를 받으면 다음과 같이 처리한다.
   - **반드시 고칠 것**: risk-checker의 "반드시 고쳐야 함"과 voice-checker의 "금칙어 사용"은 **초고 본문을 직접 고친다.** 고친 뒤 해당 에이전트를 다시 호출해 확인한다 (최대 2회). 2회 뒤에도 남으면 그대로 두고 검수 메모 맨 위에 "미해결"이라고 적는다.
   - **나머지 제안**(말투 어긋남, 평준화, 확인 필요): 본문에 반영하지 않고 검수 메모로 남긴다. 20%의 손질은 사용자 몫이다.
4. `## 검수 메모`를 채운다.

```
## 검수 메모
- voice-checker: 통과 | 수정 권장 | 수정 필요 (최종)
- risk-checker: 통과 | 수정 권장 | 수정 필요 (최종)
- 자동으로 고친 것: (금칙어·성과 보장·근거 없는 수치 등 무엇을 어떻게 고쳤는지, 없으면 "없음")
- 남은 수정 제안 (voice):
  - "<문장>" → 제안: "<문장>"
- 남은 확인 필요 (risk):
  - ...
- 미해결: (있을 때만)
```
5. 에이전트를 호출하지 못했거나 오류가 나면, 초고는 그대로 두고 검수 메모에 "검수 실패: <이유>"라고 적고 최종 보고에서 알린다. 검수 없이 통과한 것처럼 쓰지 않는다.

## 5. 최종 보고 (채팅, 짧게)
- 저장한 파일 경로
- 사용한 훅·구조 한 줄
- 검수 판정 2개와 자동으로 고친 것, 사용자가 먼저 볼 곳 1~3개
- Contents Output 저장 결과 한 줄 (5-1단계)
- 초고 전문을 채팅에 다시 붙이지 않는다 (파일에 있다).

## 5-1. Contents Output 자동 저장 (검수 직후, 필수)
이 프로젝트는 초고가 나오면 자동으로 Contents Output(관리자 페이지)에 저장하도록 되어 있다. 4단계 검수 메모를 채운 뒤 초고마다 아래를 실행한다. 별도 확인은 받지 않는다.
1. 저장: `node --env-file=.env scripts/save-output.mjs --draft drafts/<채널>/<파일>.md --commit` (키 파일(`keys/`)의 내용은 읽지 않는다. 경로는 `.env`에 있다).
   - 같은 초고를 다시 저장하면 새 문서가 쌓이지 않고 덮어쓴다 (문서 id가 초고 경로로 정해진다).
   - 검수 메모가 "(검수 중)"이거나 미해결 항목이 있으면 스크립트가 거부한다. 이 경우 저장하지 않고 최종 보고에 이유를 적는다 (`--allow-unresolved`는 사용자가 허용할 때만).
2. `body`에는 `## 초고` 본문만 들어가고 적용한 규칙·검수 메모는 들어가지 않는다 (판정 두 줄만 `meta`에 들어간다).
3. 결과(`[저장]`/`[갱신]` 문서 id 또는 거부·실패 이유)를 최종 보고에 한 줄로 적는다. 저장에 실패해도 초고 파일은 그대로 두고, 저장된 것처럼 쓰지 않는다.
4. `reports/ingest-log.md`에 날짜, 초고 제목·채널, 참고 id, 저장 결과를 한 줄 추가한다.

## 6. 자동 실행(질문 금지) 모드
`/weekly-drafts`처럼 자동으로 부르는 경우 사용자에게 질문하지 않는다. 판단이 필요하면 안전한 쪽(쓰지 않음, "확인 필요" 표시)을 고르고 기록한다. `voice.md`·`structure.md`는 어떤 경우에도 수정하지 않는다.
