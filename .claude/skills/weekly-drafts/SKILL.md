# /weekly-drafts — 주간 초고 준비 (자동 실행용, 질문 없음)

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). **사용자에게 질문하지 않는다.** 아무도 보지 않는 시간에 실행되므로 질문하면 거기서 멈춘다. 문제가 생겨도 멈추지 말고 기록하고 가능한 데까지 진행한다.

공통 절차는 **`.claude/skills/_common/draft-review.md`를 읽고 따른다** (특히 6절 자동 실행 모드).

## 절차
1. **준비**: `date +%Y-%m-%d`로 날짜를 얻고, `CLAUDE.md`, `voice.md`, `structure.md`를 읽는다. `voice.md`나 `structure.md`가 없거나 비어 있으면 8단계(실패 기록)만 하고 끝낸다.
2. **주제 후보 5개**: `/topic-ideas`의 절차 2~6을 그대로 수행한다 (결과는 `reports/topic-ideas.md`에도 쌓인다). 데이터 한계도 그대로 기록한다.
3. **상위 3개 선정**: 후보 표의 1~3번(순서가 곧 우선순위)을 쓴다. 채널 추천과 상관없이 이번 주는 **스레드 초고**를 쓴다.
4. **스레드 초고 3개**: 주제마다 `/thread-draft`의 절차를 따르되 **버전은 하나만** 쓴다 (첫 문장 훅 유형은 근거가 가장 강한 것으로 하나). 글 4~7개, 글당 500자 이하.
5. **저장**: `drafts/weekly/<날짜>/01_<슬러그>.md`, `02_...`, `03_...` (공통 절차 3의 형식, 채널 항목은 `스레드`). 같은 날짜 폴더가 이미 있으면 `<날짜>-<HHMM>`으로 폴더를 새로 만든다 (덮어쓰지 않는다).
6. **검수**: 초고마다 `voice-checker`와 `risk-checker`를 호출한다 (한 번의 응답에서 6개를 동시에 호출해도 된다). 공통 절차 4의 수정·메모 규칙을 따른다. 에이전트가 실패한 초고는 검수 메모에 "검수 실패: 이유"를 적고 다음으로 넘어간다.
7. **요약 기록**: `reports/weekly.md` **맨 위**(파일 제목 줄 바로 아래)에 오늘 항목을 추가한다. 파일이 없으면 `# 주간 초고 기록 (최신이 맨 위)`로 만든다.
```
## YYYY-MM-DD 주간 초고
- 데이터 한계: (예: 댓글 데이터 없음, 스레드 데이터 없음)
### 주제 후보 5개
1. ... (근거)
### 초고 3개
| # | 주제 | 파일 | 훅 | voice | risk | 먼저 볼 곳 |
|---|---|---|---|---|---|---|
### 실패·건너뜀
- (없으면 "없음")
```
8. **실패 기록**: 어느 단계에서든 실패하거나 건너뛴 것은 무엇이 왜 실패했는지 `### 실패·건너뜀`에 적는다. 전체가 실패해도 이 항목은 남긴다.
9. **마무리 보고**: 저장 폴더, 주제 3개, 검수 판정, 실패 여부를 짧게 알린다. 질문으로 끝내지 않는다.

## 금지
- **`voice.md`, `structure.md`를 수정하지 않는다.** 규칙 개선은 `/monthly-review`에서 사용자가 승인한다.
- 초고를 발행하거나 Firebase에 올리지 않는다 (초고는 `drafts/`에만 둔다).
- 근거 없는 수치를 쓰지 않는다 (규칙 5).
