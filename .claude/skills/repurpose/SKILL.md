# /repurpose — 대본 하나를 뉴스레터 → 스레드로 재구성

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). **입력은 원본 대본 한 줄뿐이다** (`ARGUMENTS`: `script-04` 같은 id, 또는 제목 일부).

공통 준비·저장·검수·보고는 **`.claude/skills/_common/draft-review.md`를 먼저 읽고 그대로 따른다.**

## 절차
1. **원본 찾기**: `processed/`에서 `format: 유튜브 대본`인 문서 중 id 또는 제목(`youtube_url`의 영상 제목, `key_message`)이 맞는 것을 찾는다. 후보가 여러 개면 목록만 보여 주고 고르게 한다. 없으면 `/ingest`로 먼저 올려야 한다고 알린다.
2. 공통 절차 1~2(준비, 근거 자료)를 수행한다. **사실·수치는 원본 대본에 있는 것만** 쓴다. 자막 오류가 남은 곳(`reports/ingest-log.md`의 미수정 목록)은 의미가 확실하지 않으면 빼거나 "[확인 필요]"로 표시한다.
3. **먼저 뉴스레터**를 쓴다 (`/newsletter-draft`와 같은 구조).
   - 원본의 흐름을 그대로 요약하지 않는다. 구어체 시연을 **번호 단계와 사용자의 생각**으로 다시 짠다.
   - 제목 후보 3개, 인사 → 메인(번호 단계) → 나의 생각 → 다음 편 예고(비워 둠) → 끝인사.
   - 격식체, "여러분" 대신 "분들"·"우리".
4. **그다음 스레드**를 쓴다 (`/thread-draft`와 같은 규칙, 버전은 **하나**).
   - 뉴스레터를 다시 줄이지 말고, 원본에서 **가장 눈에 띄는 결과·장면·반전 하나**를 골라 첫 글의 훅으로 삼는다 (`structure.md` 3절 훅 유형 중 하나).
   - 글 4~7개, 글당 500자 이하, 마지막 글은 행동 유도 하나 (뉴스레터나 영상 안내).
5. 각 파일을 공통 절차 3으로 저장한다. `drafts/newsletter/`와 `drafts/thread/`에 각각 저장하고, 두 파일의 메타(근거 자료)에 `원본: <id>`를 적는다. `## 적용한 규칙`에 "원본에서 무엇을 살리고 무엇을 버렸는지"를 한두 줄 적는다.
6. 공통 절차 4(검수)를 **파일마다** 수행한다 (두 에이전트를 파일 수만큼 한 번에 호출). 공통 절차 5(최종 보고)에서 두 파일을 함께 보고한다.

## 금지
- 원본에 없는 사례·수치·인용을 새로 만들지 않는다.
- 원본 영상의 성과 수치(조회수 등)를 자랑하듯 넣지 않는다 (규칙 5).

## 예시
`/repurpose script-04`
