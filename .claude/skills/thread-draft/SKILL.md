# /thread-draft — 스레드 초고 (주제 한 줄 → 3가지 버전)

작업 폴더: 이 프로젝트 폴더(저장소를 내려받은 폴더). **입력은 주제 한 줄뿐이다** (`ARGUMENTS`). 주제가 비어 있으면 그것만 묻는다.

공통 준비·저장·검수·보고는 **`.claude/skills/_common/draft-review.md`를 먼저 읽고 그대로 따른다.**

## 절차
1. 공통 절차 1~2(준비, 근거 자료)를 수행한다. 스레드 데이터는 아직 없으므로 `structure.md` 7절의 임시 규칙과 `voice.md`를 따른다.
2. **훅 유형을 다르게 3개 고른다.** `structure.md` 3절의 유형 A(하려는 일 선언), B(만든 결과 먼저), C(인사+할 일+순서), D(대상 명시) 중 이 주제에 맞는 서로 다른 3개.
3. 버전마다 다음을 지킨다.
   - 글 4~7개, 글 하나는 500자 이하.
   - 첫 글이 전부다: 훅 유형에 맞는 첫 문장으로 시작하고, 개념 설명으로 시작하지 않는다.
   - 결과·화면·경험을 먼저 보여 주고 그다음에 의미를 붙인다.
   - 마지막 글은 행동 유도 하나 (직접 해 보기, 자료 안내 등). 좋아요·팔로우 구걸은 쓰지 않는다.
   - 글마다 `1/N`처럼 번호를 붙인다.
   - 이모지와 과장 표현은 쓰지 않는다 (규칙 5, 6).
4. 공통 절차 3(저장)으로 `drafts/thread/`에 저장한다. 파일의 `## 초고` 아래에 `### 버전 1 — 훅 유형 B` 형태로 3개를 넣는다. `## 적용한 규칙`에는 버전마다 어떤 훅을 썼는지와 이유를 적는다.
5. 공통 절차 4(검수)와 5(최종 보고)를 수행한다. 최종 보고에는 세 버전의 **첫 글만** 나란히 보여 준다.

## 예시
`/thread-draft 유튜브 알고리즘보다 먼저 챙겨야 할 것`
